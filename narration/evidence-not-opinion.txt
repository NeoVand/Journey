# Evidence, not opinion
NORA: This is my favorite failure in the whole story.
THEO: [skeptical] A failure is your favorite?
NORA: A useful one. The model has made its fix, a lock around the scheduler code, and written a new test with two worker threads. Now it asks to run the tests: pytest, on the scheduler's test file.
THEO: And the harness runs it. The program on my laptop, not the model.
NORA: Always. In Claude Code and Codex, it runs inside the sandbox, the fence the operating system puts around commands, with a time limit of two minutes by default in Claude Code. In Copilot it runs in your editor's own terminal, where you can watch it, and step in if you need to.
THEO: Why does my own test suite need a fence?
NORA: Because a test is a program like any other. So is a package install, or a build script. They can touch the same files and reach the same network as anything the model asks for, so they belong inside the same fence.
THEO: Fine. It runs. Then what?
NORA: The harness captures everything. Standard out, the normal output. Standard error, the complaints. And the exit code, one number saying how it went, where zero means fine. Here it's one: failed, because the new lock deadlocks.
THEO: Deadlocks meaning...
NORA: Waiting forever for something that can never happen. Here, a thread is waiting for a lock it's already holding. It took the lock, called another method, and that method tried to take it again.
THEO: [sighs] I have written that exact bug.
NORA: Everyone has. Now here's the part people get wrong. Did the tool go wrong?
THEO: Well, the tests failed.
NORA: The tests failed. The tool worked perfectly: it ran the command, it caught the output, it reported back. It's a successful tool call whose text says failed. And for the model, it's the most useful thing it's read all session.
THEO: Because now it isn't guessing.
NORA: [warmly] Exactly. Until now, everything was the model's opinion: I think this is the bug, I think this fixes it. The test output is evidence. The harness trims long output, keeping the start and the end, and here it comes to about four hundred tokens, the small pieces of text the model reads. From those, the model can see what to change: a lock the same thread can take twice, an RLock.
THEO: [curious] If it ran a few things at once, how does it know which result is which?
NORA: Every result carries the ID of the call it answers. In Claude Code, it's a tool result block with a tool_use_id. In Codex, it's a call_id. Codex's shell can also keep a process running inside a pretend terminal, from one round trip to the model to the next, so the model can come back to it later.
THEO: And if the tests just hang?
NORA: The time limit stops them. Though the book adds a warning: killing the shell can leave a process it started still running, so the harness has to kill the whole group, or tell the model.
THEO: [thoughtful] So a red test isn't bad news. It's the first real news.
NORA: That's the best way to put it. And it's about to travel back to the model.
