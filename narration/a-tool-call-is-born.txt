# A tool call is born
THEO: So this is where it finally does something.
NORA: [amused] This is where it asks to. And the way it asks is the same way it does everything else. It writes.
THEO: Writes what?
NORA: First a special token, one the model was trained to use to open a tool call. Then the tool's name, then the arguments, all as more tokens, one at a time. In the picture they print onto a ticket, exactly as the tokens spell them.
THEO: What's on the ticket for our bug?
NORA: A search. It wants to find the scheduler code, and anywhere it uses a lock. In Claude Code that's the Grep tool, with a pattern, lock or schedule, and a path, the source folder. The arguments are written as JSON, a tidy text format of names and values, with braces and quotes.
THEO: And in the other two?
NORA: Grep is a tool of its own in Claude Code: the harness wraps ripgrep, a very fast search program, and returns matching lines with file names and line numbers. Codex has no search tool. The model writes an rg command, that's ripgrep again, into its shell tool. A simpler catalog, the same behavior.
THEO: And Copilot?
NORA: Text search sits beside the language server's symbols and a semantic index, and the model picks one.
THEO: [skeptical] How does it get the JSON right? One stray quote and the whole thing's junk.
NORA: Mostly by training. It learned to write correct JSON for the tools it was shown. There's also a strict option, if the client asks for it: a grammar built from the tool's schema blocks any token that would break the format. That costs a little speed.
THEO: And when the call's written?
NORA: It stops, and it says why. That's the stop reason. On the board here it's "tool use": I've finished a tool call, run it and send me the result. Other times it's "end turn": I'm done, show the text and wait for the person. Or it ran out of room, or a safety check stopped it.
THEO: Hang on. "End turn" sounds a lot like "the bug's fixed".
NORA: [short pause] It isn't. End turn only means the model has stopped writing. It proves nothing about your tests.
THEO: So it's like filling out a form and handing it to the front desk.
NORA: Close. Where it breaks is the handing. The model doesn't hand anything to anyone. It writes the form, and stops. Whether anyone acts on it is entirely up to the harness on your laptop.
THEO: And the red stamp on the ticket? "Valid, not yet allowed."
NORA: [warmly] My favorite bit. Valid means the shape is right: the arguments parse as proper JSON. It says nothing about meaning. The file may not exist, and the command may not be allowed. Those checks come later, on your machine.
THEO: Can it ask for two things at once?
NORA: It can write several tool calls in one reply, and the harness runs the independent ones in parallel. In this example, Claude Code's first turn also asks to fetch the lock library's docs, and both run at once.
THEO: [thoughtful] So the model never touched my code.
NORA: Never. It wrote some text shaped like a request, and stopped. A reply can carry structured tool calls, but it's still only a request. The model can ask. Only the harness can act.
THEO: Which is the bit people get wrong.
NORA: [sighs] All the time. The ticket's printed. Now it has to travel home, and be read by something that can say no.
