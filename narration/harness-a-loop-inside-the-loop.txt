# A loop inside the loop
NORA: Suppose, halfway through the fix, the model wants to know every place in the project that touches the job queue. That's a lot of searching, and a lot of reading.
THEO: And every file it reads lands in the conversation.
NORA: And stays there, riding along on every request after. So for a big side quest like that, the model can hand it to a subagent.
THEO: Another model?
NORA: Another loop. A smaller one, with its own context, meaning its own conversation, starting fresh, and its own set of tools. It gets a brief, something like: find everything that uses the queue and tell me which parts take the lock. It does the searching and reading in its own loop, and hands back a summary.
THEO: [curious] And the parent gets all the files it read?
NORA: Only the summary. That's the point. The parent's context gets a page of findings instead of everything the subagent waded through. And since each one has its own loop, several can run at once.
THEO: [amused] So it's an intern. You send them down to the archive, and they come back with a note.
NORA: Pretty much, including the part people forget. You still check the note. A summary is a claim, not proof. If it says only two places take the lock, that's worth a look before the fix is built on it.
THEO: Does it get its own copy of the code to work in?
NORA: Not unless it's given one. By default it works on the same files as everyone else. If it edits the scheduler after the parent has read it, the parent's picture of that file is out of date, and an edit it planned may no longer match what's there.
THEO: [skeptical] That sounds like a race condition. Inside the agent that's fixing my race condition.
NORA: [laughs] Same shape of problem, yes. The way out is a worktree: a second working copy of your repository, on a branch of its own, in another folder. A subagent working there can't touch your files.
THEO: Do all three agents do this?
NORA: Each in its own way. In Claude Code, the Agent tool starts one: a read-only explorer, a planner, a general worker, or one you've defined yourself, and it can work in its own git worktree. Codex has a multi-agent mode that runs several at once, and each can work in its own worktree. In Copilot, custom agents can hand work to one another, and a session can run in a worktree of its own.
THEO: So, a loop that starts a smaller loop, which brings back a summary I should still check.
NORA: That's it. And unless it has a copy of its own, whatever it changes is changed for everyone.
