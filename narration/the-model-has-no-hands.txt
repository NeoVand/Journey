# The model has no hands
THEO: I've watched my agent change a dozen files in under a minute. And you're telling me it has no hands.
NORA: [amused] Not even a finger. The model sits in a data center, and the only thing it ever does is write text. What you watched was the harness, the program on your laptop around the model, doing what that text asked for.
THEO: [curious] Okay, walk me through it. The reply is streaming back to my laptop. Then what?
NORA: It arrives in small pieces, down a long tube that ends in the harness. Plain words get printed the moment they land, which is why you see the agent typing. Thinking is shown dimmed, or summarized, or hidden. But a tool call, a request to use one of the agent's tools, is different: the harness holds on to it.
THEO: Why hold on? Just start running it as it comes in.
NORA: Because until it's complete, it's half a sentence. The tool's name might be there and the file path still on its way. So the harness waits for the call to close, then reads the whole thing as JSON, a tool name and its arguments. Only at that moment does anyone know the full request.
THEO: [skeptical] Anyone? The model wrote it.
NORA: It wrote it one token at a time, a token being a small piece of text, and each piece was sent off as it went. The harness is where the pieces come together and get read as one call.
THEO: So in our fix, what's the first thing it asks for?
NORA: A search: look for the words lock and schedule in the source folder. In Claude Code that's the Grep tool. In Codex it's ripgrep, a very fast search program, typed into the shell. In Copilot it's a text search. Three spellings, one request.
THEO: Request. You keep leaning on that word.
NORA: Because that's all it is. Picture a web form. You can type anything you like into a form on a website, and pressing submit doesn't make the server do it. The server decides.
THEO: [thoughtful] So the model can't read my file. It can only write, please read this file.
NORA: Exactly that. And everything after this point exists to decide whether to say yes.
THEO: Let me try my own picture. It's a manager giving the team instructions.
NORA: [chuckles] That's where it breaks. A manager's word carries authority, and the model's carries none. It's closer to a note slid under a door: whoever's on the other side reads it, checks it against the rules, and decides.
THEO: What if the note's garbled? Broken JSON, a tool that doesn't exist, a missing argument?
NORA: Then nothing runs. The harness writes an error into the conversation as the result of that call, and the model reads it next turn and fixes its call. A turn is one round trip: the request goes out, the reply comes back, the harness acts on it.
THEO: So a bad call isn't a crash. It's just more text for the model to read.
NORA: [warmly] Right. And that's a good habit for watching any agent. Whenever it seems to do something, translate it in your head: the model asked, the harness did.
THEO: Is this part the same in all three agents?
NORA: The packaging differs. Claude Code gets the arguments as a stream of little JSON fragments. Codex gets typed events from OpenAI's Responses API. Copilot gets chat chunks in OpenAI's style, whichever company made the model behind GitHub's service. But all three wait for the call to close before they read it.
THEO: And then they run it.
NORA: [short pause] Not yet. First it has to get past the gates.
