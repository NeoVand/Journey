# Round and round
NORA: In our example, the race condition gets fixed in ten turns. Ten trips round the same small loop, with the same few steps every time.
THEO: [skeptical] The same steps? Searching, reading, editing and testing sound like different work to me.
NORA: The model asks for different things. But the harness, the program on your machine, goes through the same steps every time. First, it packs everything into one request and sends it: the instructions, the tools, and the whole conversation so far.
THEO: Everything? Even on turn nine?
NORA: [short pause] Everything, every turn. Second, it reads the reply as it streams in, a piece at a time, instead of waiting for the end.
THEO: And third?
NORA: If the reply asks for a tool, the harness checks the call. Is it allowed, does it need you? Only then does it run. Say the model asks to search the code for the word lock. The search runs on your machine, and the model never touches it.
THEO: And fourth?
NORA: It writes down what happened: the call, and what came back, say fourteen matching lines. That goes onto the end of the conversation. Then round again, and the next request carries the result to the model.
THEO: [amused] So it's a REPL. Read, evaluate, print, loop.
NORA: Close. Where it breaks is who types. In a REPL, you write every line. Here the model writes the next line, and the harness decides whether to run it.
THEO: Can it ask for more than one thing at a time?
NORA: It can. If the calls don't depend on each other, the harness runs them side by side. On the first turn of our fix, it searches the code and fetches the library's docs together.
THEO: Is ten turns normal?
NORA: A real fix takes five to thirty. Ours had a failed test run in the middle, then another edit, then green.
THEO: And who decides it's done? Something has to say stop.
NORA: The rule is simple. It stops when a reply comes back without asking for a tool. In our example that's the tenth turn: the whole test suite has passed, and instead of another request, the model writes a summary.
THEO: So no tool call means the bug's fixed.
NORA: [thoughtful] It means the model has stopped asking. That's not quite the same thing. A model can stop, sure it's done, with the bug still there. The signal hands the floor back to you. Whether the race condition is really gone is what the tests, and your own eyes, are for.
THEO: Pack and send, read, check and run, write it down. Then again, until the model stops asking.
NORA: That's the heart of the harness. Small steps, each one checked, round and round.
