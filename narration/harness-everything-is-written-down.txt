# Everything is written down
THEO: I've lost a fair bit of work to a terminal window I closed by mistake.
NORA: [chuckles] Not this kind, usually. Everything the agent does is written down as it goes.
THEO: Written down where?
NORA: In the transcript. That's the full record of the session: your prompt, every reply, every tool call and every result. The search for lock, the lines of the scheduler it read, the edit, the failing test, the fix. Each step goes on the end.
THEO: And that's kept somewhere?
NORA: It's saved to disk, so a session can be picked up again later. Claude Code keeps each session as a file under ~/.claude, and claude --resume picks one up. Codex keeps them under ~/.codex, and codex resume does the same. In Copilot, VS Code keeps the chat sessions, and Agent Host sessions even outlive closing the folder.
THEO: [skeptical] Here's my worry, though. Every turn sends the whole conversation to the model, and the conversation only grows.
NORA: So eventually it meets a wall: the context window. That's the most the model can take in at once, measured in tokens, the small pieces of text the model reads. Think of it as the size of the model's desk.
THEO: And a long session fills the desk.
NORA: Read enough files, run the tests enough times, and it gets close. So the harness compacts. A separate model call writes a summary of the session: the task, what was decided, which files changed, what's still to do. In what gets sent, that summary takes the place of the older messages, and the latest turns, the last few round trips, stay exactly as they were.
THEO: So the model forgets how the session started.
NORA: It keeps the gist and loses the detail. Say the summary notes that the first test run deadlocked. The model no longer sees the full output that said so.
THEO: [thoughtful] Like reading my notes from a meeting instead of watching the recording.
NORA: Close, and the recording isn't thrown away. The saved transcript on your disk keeps every message. Compaction changes what's sent to the model, not what's kept.
THEO: Is there a catch?
NORA: A small one. The provider can reuse its work on the start of a request only while that start stays exactly the same, and the summary changes it. So that saved work is lost once, and built up again.
THEO: Two records, then. A complete one on my disk, and a short one that fits on the desk.
NORA: [warmly] That's it exactly. Nothing leaves the record. Some of it just stops travelling.
