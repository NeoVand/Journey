# Packed fresh, every turn
THEO: I'd always assumed the harness sends my new message, and the provider remembers the rest.
NORA: Natural guess, but usually it's the opposite. Every turn, meaning every round trip to the model, the harness on your laptop builds the whole request again, from the top.
THEO: The whole thing?
NORA: The whole thing. The harness's own instructions. Your project's rules. A snapshot of where you are: the folder, the git branch, the operating system, the date. Every tool. And the conversation so far, from "Fix the race condition in the job scheduler" right up to the latest test result.
THEO: [skeptical] By turn eight, that's a lot of text going out again.
NORA: It would be, without one trick. The provider, the company running the model, can reuse the work it already did on the start of a request, if that start matches a recent one byte for byte, and its saved work is still kept.
THEO: So the order matters.
NORA: The order is everything. The parts that never change go first: the instructions, the rules, the tools. The conversation goes last, and it only grows at the end. Turn eight begins with the same text as turn seven, plus a little more.
THEO: Like a letter where the first nine pages are always the same, and I only add a postscript.
NORA: [amused] And the post office has already read those nine pages and kept its notes, usually for a few minutes. Change one comma on page one and the notes are no use. So when something small changes, like the date or the git status, Claude Code leaves its opening alone and sends the change as a note at the end.
THEO: And the rules come from where?
NORA: A file in your project. Claude Code reads CLAUDE.md. Codex reads AGENTS.md, once, at the start of the session, which is why a change to it needs a restart before it counts. Copilot rebuilds its prompt every turn as well, with the fixed parts first.
THEO: [curious] Where do skills fit in?
NORA: A skill is a folder of instructions for one kind of task. How your team writes database migrations, say. You can end up with a lot of them.
THEO: And all of that rides along on every turn?
NORA: Just a sliver of each. A skill waits on its shelf as a name and one line about what it's for. Only the one the task needs gets unpacked. Copilot's, for instance, are SKILL.md folders it shares with Copilot CLI.
THEO: [thoughtful] So it's fresh every turn, and mostly identical every turn.
NORA: Built new each time, in an order that lets the provider skip the work it's already done.
